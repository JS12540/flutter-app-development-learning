# Flutter Directory Structure

A Flutter project contains **your app code**, plus platform-specific folders for Android, iOS, web, etc.

Your project looks like this:

```text
hello_flutter/
├── lib/
├── android/
├── ios/
├── web/
├── windows/
├── macos/
├── linux/
├── test/
├── pubspec.yaml
├── analysis_options.yaml
└── .metadata
```

---

# Where Flutter Code Starts

Flutter app code usually starts here:

```text
lib/main.dart
```

Typical starting file:

```dart
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}
```

The real entry point is:

```dart
void main()
```

Then Flutter launches your first widget through:

```dart
runApp(...)
```

So the flow is:

```text
lib/main.dart
   ↓
main()
   ↓
runApp()
   ↓
Your root widget
   ↓
App UI
```

# Important Flutter Folders

## `lib/`

This is the most important folder.

```text
lib/
└── main.dart
```

This is where your Dart and Flutter code lives.

You usually create folders like:

```text
lib/
├── main.dart
├── screens/
├── widgets/
├── models/
├── services/
└── utils/
```

Example:

```text
lib/screens/home_screen.dart
lib/widgets/custom_button.dart
```

---

## `android/`

This contains the native Android project.

```text
android/
├── app/
├── gradle/
├── build.gradle.kts
├── settings.gradle.kts
└── gradle.properties
```

Flutter uses this folder when building an Android app.

Inside:

```text
android/app/src/main/AndroidManifest.xml
```

This file contains Android-specific app configuration, such as:

```text
permissions
app name
launcher activity
internet access
Android themes
```

Example permission:

```xml
<uses-permission android:name="android.permission.INTERNET"/>
```

---

## `ios/`

This contains the native iOS project.

Used when building for iPhone or iPad.

```text
ios/
├── Runner/
├── Runner.xcodeproj
└── Runner.xcworkspace
```

You do not need this if you only care about Android.

---

## `web/`

Used when building Flutter as a website.

```text
web/
├── index.html
├── manifest.json
└── icons/
```

You do not need this if you only care about Android.

---

## `windows/`, `macos/`, `linux/`

These are desktop platform folders.

```text
windows/
macos/
linux/
```

You only need them if you want your Flutter app to run as a desktop app.

---

## `test/`

This contains tests.

```text
test/
└── widget_test.dart
```

You can keep it, delete it, or use it later.

---

# Important Files

## `pubspec.yaml`

This is one of the most important files.

It controls:

```text
app name
dependencies
assets
fonts
Flutter SDK settings
```

Example dependency:

```yaml
dependencies:
  flutter:
    sdk: flutter
  http: ^1.2.0
```

Example assets:

```yaml
flutter:
  assets:
    - assets/images/
```

---

## `.dart_tool/`

Generated by Flutter.

Do not edit manually.

---

## `.idea/`

IDE settings, mainly for Android Studio / IntelliJ.

Not app code.

---

## `build/`

Generated build output.

Do not edit manually.

Can be deleted safely.

Flutter will recreate it.

# How to Create Android-Only Flutter Project

When creating a new Flutter project, use:

```bash
flutter create --platforms=android hello_flutter
```

This creates only:

```text
hello_flutter/
├── android/
├── lib/
├── test/
├── pubspec.yaml
└── other Flutter config files
```

No iOS, web, Windows, macOS, or Linux folders.

---

# How to Remove Other Platforms From Existing Project

Since you already have the project, you can delete these folders:

```text
ios/
web/
windows/
macos/
linux/
```

Keep these:

```text
android/
lib/
test/
pubspec.yaml
analysis_options.yaml
```

After deleting, run:

```bash
flutter clean
flutter pub get
```

Then run Android:

```bash
flutter run
```

# Summary

| Folder/File     | Meaning                         |
| --------------- | ------------------------------- |
| `lib/main.dart` | Flutter app starts here         |
| `lib/`          | Your Dart/Flutter code          |
| `android/`      | Native Android project          |
| `ios/`          | Native iOS project              |
| `web/`          | Web build files                 |
| `windows/`      | Windows desktop build files     |
| `macos/`        | macOS desktop build files       |
| `linux/`        | Linux desktop build files       |
| `pubspec.yaml`  | Dependencies and app config     |
| `test/`         | App tests                       |
| `build/`        | Generated output                |
| `.dart_tool/`   | Flutter generated tooling files |

For Android-only development, mainly focus on:

```text
lib/
android/
pubspec.yaml
```


Flutter's main value proposition is:

> **Write most of your app once in `lib/` and deploy it to multiple platforms.**

## How it works

You write your UI and business logic in:

```text
lib/
├── main.dart
├── screens/
├── widgets/
├── services/
└── models/
```

Example:

```dart
class LoginScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: Text("Login"),
      ),
    );
  }
}
```

This same code can run on:

* Android
* iOS
* Web
* Windows
* macOS
* Linux

without rewriting the UI.

---

## What happens during release?

When you run:

```bash
flutter build apk
```

Flutter:

1. Reads code from `lib/`
2. Compiles Dart code
3. Uses the `android/` project as a wrapper
4. Produces:

```text
build/app/outputs/flutter-apk/app-release.apk
```

For iPhone:

```bash
flutter build ios
```

Flutter:

1. Reads same code from `lib/`
2. Uses the `ios/` project
3. Produces an iOS app

For web:

```bash
flutter build web
```

Produces:

```text
build/web/
```

which can be hosted on any web server.

## Then why do platform folders exist?

Because every platform has some native configuration.

### Android

```text
android/
```

Contains:

* Android permissions
* Gradle configuration
* App icon
* Android SDK settings

Example:

```xml
<uses-permission android:name="android.permission.CAMERA"/>
```

---

### iOS

```text
ios/
```

Contains:

* Xcode project
* Apple permissions
* Signing certificates

Example:

```xml
NSCameraUsageDescription
```

## Typical split

In many Flutter apps:

```text
95% Flutter code
5% Platform-specific code
```

Most developers spend nearly all their time in:

```text
lib/
```

and rarely touch:

```text
android/
ios/
```

unless they need:

* Push notifications
* Camera
* Bluetooth
* Native SDK integrations
* Deep links
* Platform-specific permissions

## Mental model

Think of Flutter like this:

```text
            Flutter Code
                (lib/)
                    |
    -----------------------------------
    |         |         |            |
 Android     iOS      Web       Desktop
(android)   (ios)   (web)    (windows/mac/linux)
```

The `lib/` folder is your actual application.

The platform folders are mostly adapters/wrappers that allow the same app code to run on different operating systems.

So for your learning project, you can safely think:

> "Everything important goes in `lib/`. The `android/` folder only helps package and run my Flutter app on Android." 🚀
